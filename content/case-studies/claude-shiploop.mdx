## 1. Cold open

Every case study on this site has a receipt — a commit hash, a DEVLOG
entry, a screenshot. The receipts are useful. They aren't the thing.

The thing is the methodology that produced them. Seven Claude Code
skills that classify incoming requests, route them to the right lane,
run spec/plan/tasks before any code moves, document outcomes in a
structured log, promote recurring lessons to a stable-rules file, and
consult a domain-expert subagent before merge. One installer that drops
the whole protocol into any project's `.claude/` directory in a single
`curl | bash`. A scorecard parser that reads the artifacts the
methodology produces and emits a JSON of five measured metrics per
project — discipline, rework ratio, time to ship, tokens, expert hit
rate. Numbers, not vibes. Null where the signal is not reconstructable.

This case study ships simultaneously with the repo. If you want to
install it, the one-liner is at [/tools](/tools). If you want the raw
receipts, [/scorecard.json](/scorecard.json) is the JSON. If you want
the story of why it exists and what we had to decide to get it out the
door, keep reading.

## 3. Context — why open-source it now

The methodology has been running on five client projects and this
portfolio for 21 days. Enough signal to measure. Enough rough edges
sanded. The question was never *should it be public*, it was *what
counts as ready*.

Three gates had to close before the repo could leave my laptop:

1. **Scorecard existed.** Numbers, not slogans. Discipline, rework ratio,
   time to ship, tokens, expert hit rate — one JSON per project, parser
   source open, every methodology claim checkable against git. If any
   number was hand-waved, the whole thing read as marketing.
2. **Sanitization sweep.** Skills under `.claude/skills/` had absolute
   paths and one hard-coded owner name. Capsules under `.claude/expertise/`
   had enough project-specific detail to be privacy-sensitive. Both had
   to be solved before the first push, not patched after.
3. **Install path verified.** `curl | bash` works, or the first user
   tries it, hits a `stat -c` on macOS, and never comes back. Dual-
   platform tested in two shells against a `mktemp -d` target.

All three closed on 2026-10-15. Repo pushes on 2026-10-16.

## 4. Problem — the attribution scan that killed a feature

<ValueStatement eyebrow="Spec §10.1 — resolved against the spec">
  Honest nulls over fabricated numbers.
</ValueStatement>

The spec committed to reconstructing token counts for the three Tier 0
case studies (Lexora, SMM Factory, Angel Trucking) by attributing
sessions from the shared home-directory Claude logs via keyword scoring
and physically moving matched sessions into per-project folders.

<TechnicalDetail>
  The attribution script scored 123 mixed sessions in `~/.claude/projects/-Users-ruslan/`
  against each project's keyword set (slug, product names, stakeholder
  names, domain terms). Threshold: ≥3 hits = candidate match. Classification:
  SINGLE (one project ≥3), MIXED (≥2 projects ≥3), UNCLASSIFIED (none ≥3).
  Bail-out criterion locked in the spec: if `SINGLE / total < 50%`, fall
  back to null tokens for Tier 0 and name it in the methodology aside.
</TechnicalDetail>

The scan ran. Results: SINGLE 0, MIXED 2, CONTEXT_ONLY 3, UNCLASSIFIED 118.
Angel Trucking: zero hits across all 123 sessions — it never ran from
this home directory. Lexora and SMM Factory were present only inside
two mega-sessions (97MB + 163MB) interleaved with Fieldmark, Portfolio,
and Noble SaaS work. Not cleanly separable without time-slicing we
hadn't built.

Bail-out triggered. Three cells on the scorecard became `null` instead
of fabricated estimates. The spec section that would have taught the
move script got replaced with the paragraph you're reading. The
`/tools` methodology aside carries the explanation forward.

**Lesson:** *a diagnostic scan is cheaper than a destructive filesystem
operation. The two minutes of read-only script saved hours of
reorganizing files to produce numbers that would have had no signal.*

## 6. Prompt Architecture

<PromptLog title="Rules that stayed stable across all 15 sprints">
Nothing gets built without passing through /shiploop-start or an
explicit spec + plan + tasks triple in specs/&lt;feature&gt;/.

Save `memory/` file at each phase boundary. Classify every request
before responding. The lane is the first decision; the code is the
last. Never invent numbers; null is honest.
</PromptLog>

The system prompt that produces every session is in `CLAUDE.md` at the
repo root. The 10-lane classification table is the first thing it
loads. The skills in `.claude/skills/` are single-purpose SKILL.md
files that Claude Code invokes on `/<skill-name>` — not plugins, not
frameworks, just prompts with argument hints.

## 7. Iteration Moment — the lockstep guard that wasn't

<BeforeAfter
  dateBefore="2026-10-15 20:14"
  before="`REQUIRED_CONFIG_VERSION` imported from the same `scorecard.config.mjs` file as `configVersion`. Both operands resolve to one source — the comparison can't fail. Spec §4.2 commits to the guard, parser pretends to enforce it, it has never actually run."
  dateAfter="2026-10-15 20:38"
  after="`const REQUIRED_CONFIG_VERSION = 1` hardcoded in `scorecard.mjs` AND `snapshot-check.mjs`. Export removed from both config files. />

**Lesson:** *for any `A vs B` check, trace both operands' provenance. If
they resolve to the same source file, you don't have a check — you have
a tautology that reads like one. The fix is to pin the required version
in the consumer, independent of the producer.*

## 9. Attribution procedure sidebar

<TechnicalDetail>
  The Phase A scan script (`scripts/attribute-sessions.mjs` in the
  portfolio repo) is intentionally not shipped in the OSS repo — it is
  diagnostic tooling, not methodology. It took ~2 minutes to read 123
  sessions across 269MB of mixed home-dir logs, scored each against
  per-project keyword sets, and emitted a CSV classifying each session
  as SINGLE / MIXED / CONTEXT_ONLY / UNCLASSIFIED.

  The whitelist of expected sanitization hits lives at
  `tmp/sanitization-whitelist.txt` in the OSS staging repo — gitignored,
  but documents intent for the two deliberate placeholder edits
  (`.claude/skills/shiploop-brainstorm/SKILL.md` line 92: `Owner: Ruslan |
  Claude | TBD` → placeholders; `shiploop-skill-builder/SKILL.md` line
  29: `~/shiploop/skills/` → `~/.claude/skills/`).
</TechnicalDetail>

For non-engineers evaluating the methodology: the attribution procedure
is a one-off scan that proved three case-study slugs could not have
their token spend reconstructed from a shared log. The reconstruction
would have been nice-to-have; its absence is the Null state everywhere
you see a dash on the scorecard. The methodology does not depend on
reconstructing legacy numbers — it depends on measuring new ones going
forward.

## 10. Measurement algorithm — see /tools

The full formula table lives at [/tools](/tools) under *Methodology*.
Short version:

- **Discipline** = `(hasSpec + hasPlan + hasTasks + hasDevlog) / 4`,
  binary per criterion.
- **Rework** = `fix_commits ÷ feat_commits`, from conventional-commit grep.
- **Time to ship** = median of `(ship_commit_date − spec_frontmatter_date)` per feature.
- **Tokens** = sum of `input + output + cache_creation` across session JSONL. Cache reads are excluded (10% price; dominate raw volume on long sessions).
- **Expert hit rate** = `plan_changed_yes ÷ (yes + no)`, parsed from DEVLOG.

Every number carries a `tokenSource` context tag (direct / home-dir-attribution
/ unmeasurable) so the viewer knows the lineage. Null cells get a `notes`
tooltip explaining why the signal was not reconstructable.

## 12. Reflection

<Pullquote attribution="DEVLOG · Sprint 15 · Phase B lesson">
  Null is honest; it means the signal was not reconstructable, not that
  the project failed.
</Pullquote>

Three takeaways from running the methodology on itself:

1. **The sprint that produced ShipLoop ran under ShipLoop.** Spec/plan/tasks
   triple at `specs/15-claude-shiploop-oss/`. DEVLOG entries per phase. Memory
   checkpoints at each boundary. The scorecard parser caught its own
   broken lockstep guard before the first push. Dogfooding isn't a slogan;
   it's the thing that keeps the methodology from drifting away from what
   it claims to be.
2. **"Null is honest" survives first contact.** The spec committed to it in
   §10.1. Phase A tested the commitment: the attribution scan would have
   produced marginal, misleading numbers if we'd run it anyway. Bail-out
   executed. Three scorecard cells show `—` instead of fabricated tokens.
   This is the only version of the project where the credibility
   argument holds.
3. **Linters that fail on the author's own corpus are configured wrong.**
   First skill-lint pass failed all 7 shipped skills. The right rule is
   "catch structural breakage that would prevent install," not
   "enforce the author's prose style." Trimmed back; green.
