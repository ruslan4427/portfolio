## Segment 2 — Q1: the problem + the memory folder (0:15–1:30, ~180 words, H↔G)

**Visual.**
- 0:15–0:22 → INTERVIEWER face card, paper backdrop.
- 0:22–0:32 → GUEST face card intro to answer.
- 0:32–1:00 → SCREEN shot-01 (`ls memory/`), voice-over continues.
- 1:00–1:30 → SCREEN shot-02 (`cat feedback_css_cascade_first.md`) with
  2-sec voice pause at 1:12 to let the viewer actually read a line.

**Delivery notes.** H asks conversationally, not TV-anchor. G opens with
the direct answer, not the throat-clear.

> **H:** Every large language model, in every session, starts from zero.
> It forgets everything. How do you actually solve that in a project
> that ships across, what, twelve sprints?

> **G:** Seventeen markdown files in a folder. That's the whole thing.
> Not a vector store, not a database — just files, with frontmatter, one
> file per idea, organized by what it's for. User, feedback, project,
> reference. What's on screen right now is one of them. It's a rule
> about the CSS cascade, born from one wasted hour debugging Tailwind
> on an anchor tag.
> — pause —
> That hour paid for itself the next session, and every session after.
> And unlike a vector store, I can read it. I can delete a line I
> disagree with. I can grep it. The persistence layer is legible on
> purpose — because the person maintaining it is a human, not a model.

*(88 spoken + 82 spoken = 170 words)*

## Segment 3 — Q2: the index file (1:30–2:05, ~90 words, H↔G)

**Visual.**
- 1:30–1:35 → INTERVIEWER face card.
- 1:35–1:42 → GUEST face card intro.
- 1:42–2:05 → SCREEN shot-03 (`cat MEMORY.md | head -20`).

**Delivery notes.** H's question is the reasonable pushback — G's answer
should feel like "yes, obviously" not "let me convince you."

> **H:** So does Claude read all seventeen files at the start of every
> session? That sounds expensive.

> **G:** No. It reads one — an index file. The index has a one-line
> hook per memory, so Claude knows the shape of every file without
> opening it. When something in the current turn matches a hook, Claude
> pulls that file in. First-turn context is small; recall is on-demand.
> The pattern's not new. Nobody talks about applying it to memory.

*(24 + 67 = 91 words)*

## Segment 4 — Q3: the classifier (2:05–2:55, ~140 words, H↔G)

**Visual.**
- 2:05–2:12 → INTERVIEWER face card.
- 2:12–2:18 → GUEST face card intro.
- 2:18–2:55 → SCREEN shot-04 (CLAUDE.md ShipLoop table). Text overlay
  appears at 2:35 showing the 9 classes as a vertical list on the right
  third, ink on paper, 0.3s fade.

**Delivery notes.** G reads the classes at a clip — not fast, not soulful.
Scaffolding.

> **H:** You mentioned a classifier earlier. Nine classes for every
> message you send. That sounds like the kind of ceremony that makes
> people abandon the discipline after week two. Why isn't it just
> overhead?

> **G:** It's the opposite. Every message gets classified before Claude
> responds. Question, bug, small feature, large feature, refactor,
> testing, discovery, memory, observer. The class picks the model —
> Haiku for fast, Sonnet for middle, Opus for the ones that shape
> architecture. The class also picks the ceremony. A bug gets diagnosed,
> fixed, logged. A large feature gets a written spec before a single
> line of code is allowed. Nothing gets built by accident. When people
> say AI is unreliable, what they usually mean is they let the AI decide
> what kind of turn it was. That's the unreliability. Not the model.

*(17 + 128 = 145 words)*

> **H:** Okay, prove it. Every AI-workflow demo I've seen makes big
> claims and shows you a screenshot from three weeks ago. Show me the
> numbers you just quoted actually match what's on disk right now — not

> **G:** Twelve sprints in eight calendar days. Twenty-five journal
> entries. Nine of them graduated into a rules file that Claude reads
> before anything else — that's a thirty-six-percent promotion rate,

> Low means we're solving the same problem twice. And a script runs at
> build time to make sure every number I just said matches what's on
> disk. So this video can't quietly rot either.
